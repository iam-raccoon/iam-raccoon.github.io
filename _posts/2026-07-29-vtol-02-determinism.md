> 고정익으로 경로점 네 개를 지나야 한다. 규정은 **각 점 수평 2 m 이내**. 실측 오차를 거꾸로 넣어 미리 비트는 방법 (predistort) 으로 한 점의 오차를 15 m → 1 m 아래로 줄였지만, **PC 가 바뀌면 깨졌다**. 같은 PC 에서도 판마다 ±10 m 씩 달랐다. 원인은 제어 루프가 **벽시계 타이머**로 돌고 있던 것. 센서 메시지가 올 때마다 돌게 바꾸자 세 번 돌려 8.1 / 8.1 / 8.0 m, **PC 두 대가 완전히 같은 답** 을 냈다.
{: .prompt-info }

## 배경

조난 지점까지 고정익으로 날아간다. 경로는 최소 선회 반경 원호를 이은 Dubins 경로이고, PX4 의 고정익 경로 추종기 (NPFG) 가 따라간다. 규정은 **각 경로점 수평 오차 2 m 이내**.

문제는 급한 코너였다. 비행기는 코너를 안쪽으로 질러 버린다. 한 코너 (경로점 4) 에서 15 m 씩 빗나갔다.

## v1.0 : 실측 오차를 거꾸로 넣기

빗나간 방향과 거리를 재서, 그만큼 경로점을 반대로 옮겨 놓았다 (empirical predistort).

```text
FW_WP_SHIFT  예 : WP4 (13.5, −5.3) m
```

경로점 4 오차 15 m → 0.3 ~ 0.9 m. 갈 때 4 / 4 가 2 m 안, 돌아올 때 3 / 4.

> 먼저 운동학 시뮬로 비틀 양을 계산해 보려 했다. 그런데 운동학 모델은 실제로 질러 가는 양을 **3.8 m 로 예측했고, 실제는 15 m**였다. 계산 대신 실측을 쓴 이유다.
{: .prompt-tip }

## 다른 PC 에서는 깨졌다

PC 세 대로 튜닝을 나눠 돌렸더니 같은 코드가 PC 마다 다른 결과를 냈다. 같은 PC 에서도 경로점 2 · 4 가 판마다 **±10 m** 씩 흔들렸다. 이러면 실측 오차를 거꾸로 넣는 방법이 성립하지 않는다. 기준이 되는 '실측' 이 매번 다르기 때문이다.

> 비트는 양을 반대로 넣어 보기도 했다. 오차가 8 → 16 m 로 **발산** 했다. 비튼 양에 대한 응답 기울기를 재 보니 −2.23 — 넣은 것보다 두 배 넘게 반대로 튀었다. 구조적으로 안 되는 방법이었다.
{: .prompt-warning }

그 사이에 고친 것 :

- **EKF 수렴 문턱** : 위치 · 고도 추정이 3초 동안 유효해야 시동
- **급코너 (경로점 3, 24°)** : 추종기 주기 (NPFG_PERIOD) 12 → 9 → 오차 3.4 → 0.4 ~ 0.7 m

## 원인 : 벽시계로 도는 제어 루프

제어 루프가 **실제 시간 20 Hz 타이머**로 돌고 있었다. 그런데 시뮬레이터의 시간은 PC 사양 · 부하에 따라 실제 시간보다 빠르거나 느리게 간다. 그러면 같은 비행이라도 제어 명령이 **비행의 어느 순간에 들어가는지**가 PC 마다, 판마다 달라진다.

그래서 루프를 **위치 메시지가 도착할 때마다** 돌게 바꿨다. PX4 SITL 은 시뮬레이터와 한 걸음씩 맞춰 (lockstep) 돌기 때문에, 위치 메시지에 묶으면 제어 명령도 시뮬레이터의 시간에 묶인다.

```python
# 초기화 : 센서 구동이면 벽시계 타이머를 아예 만들지 않는다 (명령 중복 방지)
if not CTRL_ON_SENSOR:
    self.create_timer(CONTROL_DT_S, self._control_loop)

def _cb_local_pos(self, msg: VehicleLocalPosition) -> None:
    ...
    self._local_pos = msg
    # 경로 재계산용 짧은 위치 버퍼 (③편)
    self._pos_buf.append((float(msg.x), float(msg.y)))
    if len(self._pos_buf) > FW_RECEDING_SETTLE_N:
        self._pos_buf.pop(0)
    ...
    # 센서 구동 제어 루프 : 이 콜백 (lockstep 시뮬과 동기) 에서 실행
    #   → 명령이 시뮬 step 과 위상 고정 = 판마다 같은 결과
    if CTRL_ON_SENSOR:
        self._control_loop()
```

설정 한 줄 (`CTRL_ON_SENSOR`) 로 예전 방식으로 되돌릴 수 있게 남겨 뒀다.

| | 경로점 2 오차 (3번 반복) | PC 사이 |
|---|---|---|
| 타이머 구동 | 판마다 ±10 m | 다름 |
| **센서 구동** | **8.1 / 8.1 / 8.0 m** | **완전히 같음** |

오차 자체는 아직 컸지만, **같은 입력에 같은 답** 이 나오게 된 게 이 단계의 성과였다. 그래야 무엇을 고쳐서 좋아졌는지 말할 수 있다.

## 메시지 형식이 바뀐 PX4 v1.17

PX4 v1.17 은 일부 메시지에 버전을 붙였다 (`_v1`). 로그에 "sequence size exceeds remaining buffer" 경고가 쏟아져서 새 버전 토픽만 구독하게 바꿨다. 그랬더니 이번엔 **해석이 깨진 쓰레기 메시지** (전부 0, 홈 고도 3,231 m) 가 들어와 좌표가 무너졌다.

여러 토픽 구독으로 되돌리고, 말이 안 되는 값은 걸렀다. 이때 주의할 점이 하나 있다. 쓰레기 값을 버린다고 **제어 루프까지 건너뛰면 안 된다**. 위치 콜백이 루프를 돌리는 구조라 루프가 멈추면 PX4 로 가는 명령이 끊기고, 오프보드 안전장치가 걸려 시동이 꺼진다. 그래서 값은 버리되 루프는 **마지막 정상 위치로** 계속 돌린다.

```python
def _cb_local_pos(self, msg: VehicleLocalPosition) -> None:
    # _v1 토픽 역직렬화 쓰레기 (거대값 / 전부 0) 방어
    _bad = (abs(msg.x) > 5000.0 or abs(msg.y) > 5000.0 or abs(msg.z) > 1000.0
            or (self._home_pos_set
                and msg.x == 0.0 and msg.y == 0.0 and msg.z == 0.0
                and msg.vx == 0.0 and msg.vy == 0.0 and msg.vz == 0.0))
    if _bad:
        if CTRL_ON_SENSOR and self._local_pos is not None:
            self._control_loop()      # 값은 버리고, 루프는 마지막 정상 위치로 계속
        return
    self._local_pos = msg
    ...
```

## RC 가 없는 시뮬에서 천이 대신 귀환

시뮬에는 조종기 (RC) 가 없다. PX4 기본 설정은 조종기 신호가 끊기면 **귀환 (RTL)**으로 넘어간다. 그래서 고정익 천이를 해야 할 순간에 드론이 집으로 돌아갔다. 오프보드 신호를 잃었을 때의 동작을 정지 (Hold) 로 바꿨다.

```text
param set-default COM_OBL_RC_ACT 5
```
