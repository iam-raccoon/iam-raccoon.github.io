> 고정익으로 경로점 네 개를 지나야 하고, 규정은 각 점 수평 2 m 이내다. 실측 오차를 거꾸로 넣어 미리 비트는 방법(predistort)으로 한 점의 오차를 15 m에서 1 m 아래로 줄였지만, PC가 바뀌면 깨졌다. 같은 PC에서도 판마다 ±10 m씩 달랐다. 제어 루프가 벽시계 타이머로 돌고 있던 탓이었다. 센서 메시지가 올 때마다 돌게 바꾸자 세 번 돌려 8.1/8.1/8.0 m가 나왔고, PC 두 대가 완전히 같은 답을 냈다.
{: .prompt-info }

## 배경

조난 지점까지 고정익으로 날아간다. 경로는 최소 선회 반경 원호를 이은 Dubins 경로이고, PX4의 고정익 경로 추종기(NPFG)가 따라간다. 규정은 각 경로점 수평 오차 2 m 이내다.

문제는 급한 코너였다. 비행기는 코너를 안쪽으로 질러 버린다. 한 코너(경로점 4)에서 15 m씩 빗나갔다.

## v1.0: 실측 오차를 거꾸로 넣기

빗나간 방향과 거리를 재서 그만큼 경로점을 반대로 옮겨 놓았다(empirical predistort).

```text
FW_WP_SHIFT  예 : WP4 (13.5, −5.3) m
```

경로점 4 오차가 15 m에서 0.3~0.9 m로 줄었다. 갈 때는 4/4가 2 m 안에 들었고, 돌아올 때는 3/4였다.

처음에는 운동학 시뮬로 비틀 양을 계산해 보려 했다. 그런데 운동학 모델은 질러 가는 양을 3.8 m로 예측했고, 실제는 15 m였다. 그래서 계산 대신 실측을 썼다.

## 다른 PC에서는 깨졌다

PC 세 대로 튜닝을 나눠 돌렸더니 같은 코드가 PC마다 다른 결과를 냈다. 같은 PC에서도 경로점 2와 4가 판마다 ±10 m씩 흔들렸다. 이러면 실측 오차를 거꾸로 넣는 방법이 성립하지 않는다. 기준이 되는 실측값이 매번 다르기 때문이다.

비트는 양을 반대로 넣어 보기도 했는데, 오차가 8에서 16 m로 발산했다. 비튼 양에 대한 응답 기울기를 재 보니 −2.23이었다. 넣은 것보다 두 배 넘게 반대로 튄 것이라, 이 방법은 구조적으로 안 됐다.

그 사이에 고친 것은 두 가지다.

- EKF 수렴 문턱: 위치, 고도 추정이 3초 동안 유효해야 시동을 건다
- 급코너(경로점 3, 24°): 추종기 주기(NPFG_PERIOD)를 12에서 9로 줄여 오차가 3.4에서 0.4~0.7 m가 됐다

## 벽시계로 돌던 제어 루프

제어 루프가 실제 시간 20 Hz 타이머로 돌고 있었다. 그런데 시뮬레이터의 시간은 PC 사양과 부하에 따라 실제 시간보다 빠르거나 느리게 간다. 그러면 같은 비행이라도 제어 명령이 비행의 어느 순간에 들어가는지가 PC마다, 판마다 달라진다.

그래서 루프를 위치 메시지가 도착할 때마다 돌게 바꿨다. PX4 SITL은 시뮬레이터와 한 걸음씩 맞춰(lockstep) 돌기 때문에, 위치 메시지에 묶으면 제어 명령도 시뮬레이터의 시간에 묶인다.

```python
# 초기화 : 센서 구동이면 벽시계 타이머를 아예 만들지 않는다 (명령 중복 방지)
if not CTRL_ON_SENSOR:
    self.create_timer(CONTROL_DT_S, self._control_loop)

def _cb_local_pos(self, msg: VehicleLocalPosition) -> None:
    ...
    self._local_pos = msg
    # 경로 재계산용 짧은 위치 버퍼 (③편)
    self._pos_buf.append((float(msg.x), float(msg.y)))
    if len(self._pos_buf) > FW_RECEDING_SETTLE_N:
        self._pos_buf.pop(0)
    ...
    # 센서 구동 제어 루프 : 이 콜백 (lockstep 시뮬과 동기) 에서 실행
    #   → 명령이 시뮬 step 과 위상 고정 = 판마다 같은 결과
    if CTRL_ON_SENSOR:
        self._control_loop()
```

설정 한 줄(`CTRL_ON_SENSOR`)로 예전 방식으로 되돌릴 수 있게 남겨 뒀다.

경로점 2 오차를 3번 반복해 재 보면, 타이머 구동은 판마다 ±10 m씩 달랐고 PC 사이에서도 달랐다. 센서 구동은 8.1/8.1/8.0 m였고 PC 사이에서 완전히 같았다.

오차 자체는 아직 컸지만, 같은 입력에 같은 답이 나오게 됐다. 그래야 무엇을 고쳐서 좋아졌는지 말할 수 있다.

## 메시지 형식이 바뀐 PX4 v1.17

PX4 v1.17은 일부 메시지에 버전을 붙였다(`_v1`). 로그에 "sequence size exceeds remaining buffer" 경고가 쏟아져서 새 버전 토픽만 구독하게 바꿨다. 그랬더니 이번엔 해석이 깨진 쓰레기 메시지(전부 0, 홈 고도 3,231 m)가 들어와 좌표가 무너졌다.

여러 토픽 구독으로 되돌리고, 말이 안 되는 값은 걸렀다. 이때 쓰레기 값을 버린다고 제어 루프까지 건너뛰면 안 된다. 위치 콜백이 루프를 돌리는 구조라 루프가 멈추면 PX4로 가는 명령이 끊기고, 오프보드 안전장치가 걸려 시동이 꺼진다. 그래서 값은 버리되 루프는 마지막 정상 위치로 계속 돌린다.

```python
def _cb_local_pos(self, msg: VehicleLocalPosition) -> None:
    # _v1 토픽 역직렬화 쓰레기 (거대값 / 전부 0) 방어
    _bad = (abs(msg.x) > 5000.0 or abs(msg.y) > 5000.0 or abs(msg.z) > 1000.0
            or (self._home_pos_set
                and msg.x == 0.0 and msg.y == 0.0 and msg.z == 0.0
                and msg.vx == 0.0 and msg.vy == 0.0 and msg.vz == 0.0))
    if _bad:
        if CTRL_ON_SENSOR and self._local_pos is not None:
            self._control_loop()      # 값은 버리고, 루프는 마지막 정상 위치로 계속
        return
    self._local_pos = msg
    ...
```

## RC가 없는 시뮬에서 천이 대신 귀환하던 문제

시뮬에는 조종기(RC)가 없다. PX4 기본 설정은 조종기 신호가 끊기면 귀환(RTL)으로 넘어간다. 그래서 고정익 천이를 해야 할 순간에 드론이 집으로 돌아갔다. 오프보드 신호를 잃었을 때의 동작을 정지(Hold)로 바꿨다.

```text
param set-default COM_OBL_RC_ACT 5
```
