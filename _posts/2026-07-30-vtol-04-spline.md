> [③편]({% post_url 2026-07-30-vtol-03-receding %})에서 아홉 가지 넘게 시도한 건 전부 경로를 따라가는 쪽(팔로워)을 손본 것이었음. 원인은 경로 자체에 있었음. Dubins 경로는 직선에서 원호로 넘어가는 순간 곡률이 계단처럼 뜀. 고정익은 기울기(롤)를 순간에 못 바꾸니 원호 진입점마다 밀렸음. 경로를 곡률이 이어지는 스플라인으로 바꾸자 가장 말썽이던 경로점 4가 6.5에서 0.9 m로, 경로점 3이 2.8에서 0.6 m로 줄었음.
{: .prompt-info }

## 6.5 m는 매번 같은 6.5 m였음

경로점 4는 판마다 흔들리지 않고 매번 비슷하게 6~6.5 m를 질렀음. 같은 자리에서 같은 방향으로 같은 만큼 빗나가니, 우연으로 볼 수 없었음. 구조에서 나오는 오차였음.

그동안 고친 건 전부 따라가는 쪽이었음.

- 실측 오차를 거꾸로 넣기([②편]({% post_url 2026-07-29-vtol-02-determinism %}))
- 경로점마다 다시 그리기, 시작점 평균([③편]({% post_url 2026-07-30-vtol-03-receding %}))
- 앞보기 거리, 코너 감속, 다른 유도법 이식(전부 실패)

## 곡률 계단

Dubins 경로는 직선과 최소 반경 원호로 이루어짐. 직선의 곡률은 0, 원호의 곡률은 1/R임. 그 경계에서 곡률이 0에서 1/R로 순간에 뜀.

자동차라면 핸들을 빨리 꺾으면 됨. 고정익은 선회하려면 먼저 기울어야(롤) 하고, 기우는 데 시간이 걸림. 경로는 지금부터 원을 그리라고 하는데 비행기는 아직 직선으로 날고 있음. 그 사이에 바깥으로 밀리고, 밀린 만큼 코너를 질러서 경로점을 놓침. 문제는 팔로워가 아니었음. 경로의 곡률 불연속이었음.

## Catmull-Rom 스플라인으로 곡률 잇기

각 경로점을 정확히 지나면서 곡률이 매끈하게 변하는 곡선으로 바꿨음. centripetal Catmull-Rom 스플라인(α = 0.5)은 급한 코너에서도 튀어 나가거나 뾰족하게 꺾이지 않음.

`dubins_path.py`에 새로 짠 생성기의 본체임.

```python
def wp_sequence_to_spline_points(waypoints, r_min, step_m=8.0,
                                 initial_heading_math=math.pi / 2,
                                 free_final_heading=False):
    """(north,east) WP 리스트 → 곡률연속 스플라인 dense 점 리스트."""
    W = [(float(w[0]), float(w[1])) for w in waypoints]
    if len(W) < 2:
        return list(W)

    # 팬텀 시작점 : W0 뒤쪽 (−initial_heading) → W0 접선이 현재 기수와 정렬
    d0 = math.hypot(W[1][0] - W[0][0], W[1][1] - W[0][1]) or 1.0
    p_start = (W[0][0] - d0 * math.cos(initial_heading_math),
               W[0][1] - d0 * math.sin(initial_heading_math))
    # 팬텀 끝점 : 마지막 구간 외삽
    p_end = (2 * W[-1][0] - W[-2][0], 2 * W[-1][1] - W[-2][1])

    P = [p_start] + W + [p_end]
    alpha = 0.5                               # centripetal

    def _tnext(ti, a, b):
        d = math.hypot(b[0] - a[0], b[1] - a[1])
        return ti + max(d, 1e-6) ** alpha

    out = [W[0]]
    for i in range(1, len(P) - 2):            # 구간 W[i-1] → W[i]
        p0, p1, p2, p3 = P[i - 1], P[i], P[i + 1], P[i + 2]
        t0 = 0.0
        t1 = _tnext(t0, p0, p1)
        t2 = _tnext(t1, p1, p2)
        t3 = _tnext(t2, p2, p3)
        n = max(1, int(math.hypot(p2[0] - p1[0], p2[1] - p1[1]) / step_m))
        for s in range(1, n + 1):
            t = t1 + (t2 - t1) * (s / n)
            out.append(_cr_point(p0, p1, p2, p3, t, t0, t1, t2, t3))
    out[-1] = W[-1]                           # 끝점 정확히 고정
    return out
```

`_cr_point`는 Barry-Goldman 방식으로 한 점을 계산하는 보조 함수임(선형 보간 다섯 번). 외부 라이브러리 없이 `math`만 씀. 타입 표기와 `initial_heading`이 없을 때의 분기는 생략했음.

경로를 쓰는 곳은 [③편]({% post_url 2026-07-30-vtol-03-receding %})에서 하나로 모아 둔 `_build_path`뿐이라 여기만 고치면 됐음(`fw_navigator.py`).

```python
def _build_path(self, wps, r_min, step_m=8.0,
                initial_heading_math=math.pi / 2,
                free_final_heading=False):
    """경로 생성 디스패처 : FW_PATH_MODE 로 Dubins / 스플라인 선택 (v6.0).
    팔로워 (carrot) · 천이 · WP 판정은 무손 — dense (n,e) 점 리스트 포맷 동일."""
    fn = (wp_sequence_to_spline_points if FW_PATH_MODE == 'spline'
          else wp_sequence_to_dubins_points)
    return fn(wps, r_min, step_m=step_m,
              initial_heading_math=initial_heading_math,
              free_final_heading=free_final_heading)
```

- 기존 Dubins 생성기와 입출력이 똑같게 만들었음. 경로를 따라가는 쪽, 천이, 경로점 판정, 경로점마다 다시 그리기는 하나도 안 건드리고 경로 생성만 바꿨음
- 출발점 뒤에 가상의 점을 하나 둬서 곡선의 시작 방향이 지금 기수 방향과 맞게 했음. 경로점마다 다시 그릴 때도 이어지는 부분이 부드러움
- 설정 한 줄(`FW_PATH_MODE = 'spline' | 'dubins'`)로 언제든 되돌릴 수 있음

## 결과

같은 PC에서 두 경로를 번갈아 돌렸음.

| | 경로점 2 | 경로점 3 | 경로점 4 | 경로점 5 |
|---|---:|---:|---:|---:|
| Dubins 1판 | 0.7 | 2.8 | 6.5 | 4.7 |
| Dubins 2판 | 0.7 | 2.6 | 6.0 | 3.6 |
| 스플라인 1판 | **0.8** | **0.6** | **0.9** | 3.1 |
| 스플라인 2판 | 0.7 | 0.5 | 4.1 | 9.5 |

단위는 m임. 스플라인 1판은 경로점 2, 3, 4가 모두 1 m 미만으로 지금까지 갈 때 구간 최고 기록이었고, 트레이도 0.12 m로 집었음.

- 경로점 3은 두 판 모두 2.6~2.8에서 0.5~0.6 m로 일관되게 좋아졌음
- 급한 코너에서 스플라인이 최소 선회 반경보다 더 급한 곡률을 요구해 발산할까 걱정했는데, 실제 코스(24° 코너)에서는 생기지 않았음

> 아직 확실하지 않은 부분이 있음. 비교가 두 판씩뿐이고, 스플라인 2판은 경로점 4가 4.1 m, 경로점 5가 9.5 m로 흔들렸음. 그 PC의 통신 타이밍 편차로 보고 있지만, 여러 판 통계와 실기체 검증으로 더 확인해야 함. 마지막 긴 구간(경로점 5)은 스플라인 끝점 처리 때문에 개선이 애매함.

## 정리

- 아홉 가지 실패는 전부 따라가는 쪽을 고친 것이었음. 오차가 매번 같은 자리에서 같은 크기로 났다는 점이 경로를 의심할 근거였는데, 거기까지 가는 데 오래 걸렸음
